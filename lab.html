REPAIR 01 / IMAGE PATHS

The missing Ginseng button

The idea: an image's src is a set of directions from the page to the picture file. The browser follows them exactly. Every folder name, slash, letter, and capital letter has to match the real file.

How the browser follows your path

    Step 3 Why it works

    BEFORE

    src="img/Ginseng.png"
    Ginseng

    The server looks inside img for a file named Ginseng.png. There isn't one, so it answers "404, not found." The browser shows the alt text instead.

    AFTER

    src="img/ginseng.png"

    The directions match the real file, letter for letter. The server finds img/ginseng.png and sends the picture.

    How to read a path: img/ginseng.png means "starting from the folder this page is in, open the img folder, then get the file named ginseng.png." The slash separates the folder from the file.

    Why capitals sneak up on you: Windows and Mac usually treat G and g as the same in file names, so Ginseng.png might load fine when you open the page on your own laptop. Web servers like Cloudflare and GitHub Pages treat them as different letters, so the same page breaks once it's online. It's the same trap as Huberman.jpg vs huberman.jpg from HTML-2.

    Why you saw the word "Ginseng": when an image can't load, the browser shows its alt text in its place. Good alt text tells you which image broke.

    Rule of thumb: name files in all lowercase with dashes instead of spaces (art-dealer.png), and copy and paste file names instead of retyping them.

    REPAIR 02 / JUMP LINKS

    The link that goes nowhere

    The idea: a jump link has two halves. The link says href="#tracks". The spot it jumps to says id="tracks". The name after the # has to match the id exactly, or the browser can't find where to go.

    Step 1 Spot it

    I expected clicking "Jump to the five tracks" to scroll down to the track list, but I see nothing happen at all.

    The broken page (try clicking the link)

    bmis235-html-4.pages.dev/ginseng.html

    The code (in ginseng.html)

    <a href="#Tracks">Jump to the five tracks</a>

<!-- ...the rest of the page... -->

<section id="tracks">
  <h2>Five tracks to know</h2>
  ...
</section>
    Why doesn't the link jump?

    Step 2 Fix it

    You can edit either half, or both. They just need to match. Then press Enter or Check my fix, and click the link in your version to test it.

    <a href="">Jump to the five tracks</a>

<!-- ...the rest of the page... -->

<section id="">
  <h2>Five tracks to know</h2>
  ...
</section>

    Your version (click the link to test it)

    bmis235-html-4.pages.dev/ginseng.html

    Step 3 Why it works

    BEFORE

    href="#Tracks" and id="tracks"

    The browser looks for an element whose id is exactly Tracks, capital T. The only id on the page is tracks, so it finds nothing and stays put. No error message, nothing. That's what makes this bug sneaky.

    AFTER

    href="#tracks"

    Both halves use the same name, so the browser finds the section and scrolls to it.

    The two halves: the # goes only in the link. It means "a spot on this page." The id is just the name, with no #.

    The rules for ids: exact match, capitals included. No spaces (use dashes, like five-tracks). Each id should be used only once per page.

    Jumping to another page: put the page name first, like ginseng.html#tracks. That opens ginseng.html and jumps to the tracks section.

    You've been using these already: the "01 · Image paths" links at the top of this lab are jump links to id="repair-paths" and friends.

    REPAIR 03 / THE STYLESHEET

    The page that lost its look

    The idea: one line in each page's <head>, <link rel="stylesheet" href="styles.css">, connects that page to the shared stylesheet. Every page with that line gets the same look. A page without a working link gets none of it.

    Step 1 Spot it

    I expected all four pages to have the dark background and pink headings, but I see skai.html looking like a plain white page from 1996.

    Four pages that all share styles.css

    ginseng.html's head (looks right)

    <head>
  <title>Ginseng | Behind the Sound</title>
  <link rel="stylesheet" href="styles.css">
</head>

    skai.html's head (looks plain)

    <head>
  <title>Skai | Behind the Sound</title>
  <link rel="stylesheet" href="style.css">
</head>
    Why is skai.html the only plain page?

    Step 2 Fix it

    Fix skai.html's href so it points at the real stylesheet. Then press Enter or Check my fix.

    <head>
  <title>Skai | Behind the Sound</title>
  <link rel="stylesheet" href="">
</head>

    The project's files

      Your version

      Step 3 Why it works

      What the line does: rel="stylesheet" tells the browser what the file is for. href is the path to it, so it follows the same rules as Repair 01: exact spelling, exact capitals, right folder.

      What went wrong: the browser looked for style.css, found nothing, and quietly skipped the styles. The page fell back to the browser's built-in look: white background, black Times-style text, blue underlined links. There's no error on the page itself. If you open the browser's developer tools (right-click, Inspect, then the Console tab), you'd see a 404 error for style.css. That's the fastest way to catch this bug.

      See it spread: one file, four pages

      This is the whole point of a shared stylesheet. Pick a new accent color. It's one change in one file, and watch what happens to the pages.

      /* styles.css */
:root { --pink: #F7ABCA; }

      Before your fix, skai.html would have ignored this color change completely, because it never loaded styles.css. Your real site works the same way: one styles.css styles all seven pages, including this one.

      Cheat sheet: when something's broken

      1. Missing image? Compare the src with the real file name, letter by letter: folder, slash, name, capitals, extension.
      2. Jump link does nothing? The name after # in the href must exactly match an id on the page (no # in the id, no spaces).
      3. Page lost its styles? Check the <link rel="stylesheet" href="..."> line in the <head>. The href is a path, so it follows rule 1.
      4. Still stuck? Say it in one sentence: "I expected ___, but I see ___." Then find the one line that sentence points to.
